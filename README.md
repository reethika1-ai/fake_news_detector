# 🛡️ VeriNews AI — Fake News & Misinformation Detector

A production-ready, serverless fake news and misinformation detection platform engineered with **FastAPI**, **DistilBERT** (Hugging Face Transformers / PyTorch), **Supabase**, **Vercel**, and an advanced **light-mode SaaS UI**.

---

## 📁 Project Architecture

```
fake-news-detector/
│
├── api/
│   └── index.py             # FastAPI serverless backend handler for Vercel & local dev
│
├── model/
│   ├── .gitkeep             # Directory placeholder
│   └── README.md            # Instructions for placing best_model.pt
│
├── .env.example             # Template for Supabase & model configuration
├── index.html               # Advanced light-mode SaaS frontend dashboard
├── requirements.txt         # Production Python dependencies
├── schema.sql               # Supabase SQL schema for prediction_logs table
├── vercel.json              # Vercel serverless function & routing configuration
└── README.md                # Project documentation
```

---

## 🚀 Key Features

- **⚡ DistilBERT Inference Engine**: High-throughput transformer sequence classification with automatic GPU (CUDA) and CPU device selection.
- **🛡️ Resilient Placeholder / Heuristic Mode**: If `model/best_model.pt` has not been uploaded yet, the backend boots smoothly in simulation mode, allowing end-to-end testing without crashes.
- **💾 Asynchronous Supabase Persistence**: Every evaluated article is asynchronously written into the Supabase `prediction_logs` table via background tasks, recording `news_text`, `prediction`, `confidence`, and `created_at`.
- **🎨 Modern SaaS Dashboard (`index.html`)**: Clean light-mode aesthetic using Tailwind CSS and Lucide icons, responsive text input, benchmark sample presets, live telemetry, and real-time audit feed.
- **☁️ Zero-Config Vercel Deployment**: Pre-configured `vercel.json` routing both serverless Python endpoints (`/api/*`) and static dashboard assets.

## 🛠️ Quickstart & Local Setup

### 1. Clone & Navigate
```bash
cd fakenewsdetector
```

### 2. Set Up Python Environment
```bash
python -m venv venv

# Windows (PowerShell)
.\venv\Scripts\Activate.ps1

# Linux / macOS
source venv/bin/activate
```

### 3. Install Dependencies
```bash
pip install -r requirements.txt
```

### 4. Configure Environment Variables
Copy `.env.example` to `.env`:
```bash
cp .env.example .env
```
Open `.env` and fill in your Supabase project credentials:
```env
SUPABASE_URL="https://your-project-id.supabase.co"
SUPABASE_KEY="your-anon-or-service-role-key"
```

## 🗄️ Supabase Table Setup

1. Open your [Supabase Dashboard](https://supabase.com/dashboard).
2. Go to the **SQL Editor**.
3. Run the following snippet (or run [`schema.sql`](./schema.sql)):

```sql
-- Create prediction_logs table
CREATE TABLE IF NOT EXISTS public.prediction_logs (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    news_text TEXT NOT NULL,
    prediction VARCHAR(50) NOT NULL,
    confidence NUMERIC(5, 2) NOT NULL,
    created_at TIMESTAMPTZ DEFAULT TIMEZONE('utc'::text, NOW()) NOT NULL
);

-- Performance index
CREATE INDEX IF NOT EXISTS idx_prediction_logs_created_at 
ON public.prediction_logs (created_at DESC);

-- Enable Row Level Security (RLS)
ALTER TABLE public.prediction_logs ENABLE ROW LEVEL SECURITY;

-- Allow inserts and selects
CREATE POLICY "Allow anonymous and service inserts"
ON public.prediction_logs FOR INSERT
TO anon, authenticated, service_role
WITH CHECK (true);

CREATE POLICY "Allow anonymous and service reads"
ON public.prediction_logs FOR SELECT
TO anon, authenticated, service_role
USING (true);
```

## 🧠 Placing Your Trained Model Weights

Place your trained `best_model.pt` file inside the `model/` folder:
```
model/
└── best_model.pt
```

### Supported Formats:
- **PyTorch State Dictionary**: `torch.save(model.state_dict(), "best_model.pt")`
- **Complete PyTorch Model Object**: `torch.save(model, "best_model.pt")`

*Note: If no file is placed, the application automatically runs in heuristic placeholder mode so the interface and database persistence can still be verified.*

## 📡 REST API Reference

### 1. `POST /api/predict`
Evaluates news text and stores record in Supabase.

#### Request Body:
```json
{
  "text": "A landmark study published today in the Astrophysical Journal reveals that astronomers utilizing NASA's James Webb Space Telescope have detected definitive atmospheric biosignatures on exoplanet K2-18b."
}
```

#### Response:
```json
{
  "verdict": "Real",
  "confidence": 98.45,
  "probabilities": {
    "Real": 98.45,
    "Fake": 1.55
  },
  "latency_ms": 18.24,
  "model_mode": "distilbert_weights",
  "logged_to_supabase": true,
  "created_at": "2026-11-03T11:00:00.000000+00:00"
}
```

---

### 2. `GET /api/health`
Returns system diagnostics, active device (CPU/GPU), model status, and Supabase connectivity.

---

### 3. `GET /api/logs?limit=10`
Retrieves recent evaluations from the Supabase `prediction_logs` table for dashboard feeds.

## ☁️ Deploying to Vercel

### Option 1: Vercel CLI
```bash
npm i -g vercel
vercel
```

### Option 2: GitHub Repository Connection
1. Push this repository to GitHub.
2. Import the repository into the [Vercel Dashboard](https://vercel.com/new).
3. Under **Environment Variables**, add:
   - `SUPABASE_URL`
   - `SUPABASE_KEY`
4. Click **Deploy**. Vercel will build the serverless Python handler and host the static UI.
